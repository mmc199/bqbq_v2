# 跨站镜像搜索方案（联邦聚合）

> 状态：**方案稿，尚未实施**
> 需求：把 FAB 的「导出」按钮扩展为"镜像站管理"，用户可添加其他域名
> 的同类站点，在主站一次搜索就能看到多个站点的结果。

---

## 一、结论先行

| 问题 | 结论 |
|---|---|
| 现有结构能跨域吗？ | **完全不能**。nginx 有 Basic 鉴权（实测 401），FastAPI 的 CORS 白名单只有 localhost:5173 |
| md5 查重和标签合并该谁做？ | **必须后端做**。前端合并会导致分页、排序、总数全部失效 |
| 前端合并复杂吗？ | 不只是复杂，而是**结果会错**（详见第四章） |
| 跨域是大问题吗？ | 是，但**只在"浏览器直接跨站请求"的意义上是**。方案用后端代理绕开它，浏览器始终只和自己这一站通信 |

---

## 二、架构：后端代理聚合（浏览器零跨域）

### 2.1 核心设计

```
浏览器 ──同源──> 主站后端 ──HTTP──> 镜像站 A 的 /api/mirror/search
                    │              ├──> 镜像站 B
                    │              └──> 镜像站 C
                    │
                    └─ 合并去重排序 ──> 返回统一结果给浏览器
```

**关键点：浏览器永远只访问自己的站** —— CORS 问题彻底消失，
因为服务端之间的 HTTP 调用不受浏览器同源策略约束。

### 2.2 为什么不改 CORS 白名单

即便把镜像站域名加进 `cors_origins`，仍有三个问题无法解决：

1. **nginx 鉴权**：实测 `https://bqbq.mmc199.com/api/*` 先被 nginx 拦走
   返回 401（`{"status":"error","message":"未授权"}`），根本到不了 FastAPI；
2. **N×M 组合爆炸**：5 个站互相访问要配 20 条 CORS 规则；
3. **暴露用户 IP**：浏览器直连镜像站，镜像站能看到访客真实 IP。

后端代理一次解决全部问题。

## 三、后端设计

### 3.1 数据表

```sql
-- 用户配置的镜像站
CREATE TABLE IF NOT EXISTS mirror_sites (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT NOT NULL,           -- 显示名，如「小李的表情站」
    base_url    TEXT NOT NULL UNIQUE,    -- https://xxx.com，不含路径
    enabled     INTEGER DEFAULT 1,
    priority    INTEGER DEFAULT 100,     -- 去重时谁的标签优先（小的优先）
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 3.2 镜像站需提供的接口

镜像站**不需要改造现有代码**，只要有只读的搜索接口即可。
建议按本项目的现有格式对外暴露（即 `/api/search`），但加一层
**公开只读别名** `/api/mirror/search`：

```jsonc
// GET /api/mirror/search?q=猫&page=1&page_size=20&sort_by=time_desc
{
  "total": 1234,
  "results": [
    {
      "md5": "7f5d377f...",
      "filename": "7f/5d/7f5d377f....gif",
      "tags": ["猫", "可爱"],
      "file_size": 1543129,
      "width": 640, "height": 480,
      "created_at": "2026-10-20 10:00:00",
      "url": "https://xxx.com/images/7f/5d/7f5d....gif",   // 完整可访问地址
      "thumb_url": "https://xxx.com/thumbnails/7f/5d/...._thumbnail.jpg"
    }
  ]
}
```

**`url` / `thumb_url` 必须是绝对地址** —— 前端渲染缩略图时直接用这些
URL（`<img src>` 不受 CORS 限制，可正常跨域显示）。

> **⚠️ 现有结构确实缺这个**：本项目的 `SearchResultItem`
> （`backend/app/models/image.py`）只有
> `md5 / filename / tags / w / h / size / is_trash`
> —— **没有任何 URL 字段**，连 `created_at` 都没有。
> 前端目前是用 `filename` 自己拼 `/images/...`。
> 跨站时前端不知道对方域名，所以镜像接口必须额外补 `url`、`thumb_url`，
> 并补上 `created_at`（排序需要）。

### 3.3 聚合搜索接口

```
GET /api/search/federated?q=猫&page=1&page_size=20&sites=1,2,3
```

**处理流程**

```
1. 并行请求所有启用的镜像站（asyncio.gather + 超时 3 秒）
2. 任何站点失败/超时 -> 跳过，记录到 response.sources[].status
3. 合并所有结果，按 md5 去重
4. 排序（统一按用户选的 sort_by）
5. 内存分页（取 page/page_size 那一段）
6. 返回合并结果 + 每个来源站的状态
```

**返回结构**

```jsonc
{
  "total": 245,                       // 去重后的总数
  "results": [ /* 合并后的条目 */ ],
  "sources": [
    { "site": "本机", "status": "ok",   "count": 120 },
    { "site": "小李的站", "status": "ok",   "count": 80 },
    { "site": "老王站", "status": "timeout", "count": 0 }
  ]
}
```

`sources` 让用户知道"某个站没响应"，而不是莫名少了一半结果。

### 3.4 ⚠️ 最大的技术难点：分页

**本项目搜索已支持 keyset 游标分页**（`SearchRequest.cursor_id` +
`cursor_ts` 复合游标，见 `models/image.py`），但**多站聚合无法用游标** ——
各站的 `(created_at, id)` 游标互不通用，A 站的游标拿到 B 站毫无意义。

**解决方案：聚合模式下退回 offset 分页，并设置合理的深度上限。**

| 方案 | 优点 | 缺点 |
|---|---|---|
| **offset 分页 + 深度上限（建议）** | 实现简单、结果正确 | 翻到第 50 页以后会慢 |
| 每站拉全量再本地分页 | 任意深度都正确 | 流量爆炸（45 万条不可能） |
| 只做前 N 页 | 简单 | 用户体验受限 |

**建议实现**：

- 聚合搜索限制 `page * page_size <= 1000`（即最多翻 50 页）
- 每站按 `page * page_size` 向前拉取，但**单站最多拉 500 条**
- 超过上限时返回提示："跨站搜索最多显示前 1000 条，请加标签缩小范围"

> 好在跨站搜索通常是"随便搜搜看"，深度翻页需求不高。
> **单站搜索保持现有游标分页不变**，只在启用镜像时才走 offset。

## 四、为什么不交给前端合并

| 问题 | 后果 |
|---|---|
| **分页失效** | A 站有 3 页、B 站有 5 页，合并后"第 2 页"是谁的第 2 页？ |
| **排序失效** | 两站各自排序，合并后的顺序毫无意义 |
| **每页数量不准** | 去重后一页可能只剩 12 条 |
| **流量放大 N 倍** | 5 个站 × 每页 20 条 = 100 条全量传输，穿透链路上极慢 |
| **去重规则分裂** | 前端和后端各写一套 md5 合并逻辑，必然不一致 |
| **镜像站增减要改前端** | 后端聚合只要改数据库一行 |

**结论：聚合逻辑放后端，前端只调一个接口。**

## 五、md5 查重与标签合并规则

### 5.1 去重键

**用 md5**（不区分大小写，统一转小写）。
理由：md5 是内容的哈希，同一个 md5 必然同一个文件，最可靠。

### 5.2 标签合并策略

**采用「并集 + 来源标注」**：

```jsonc
{
  "md5": "7f5d...",
  "tags": ["猫", "可爱", "猫咪", "萌"],        // 并集
  "tag_sources": {                             // 每个标签来自哪些站
    "猫": ["本机"],
    "可爱": ["本机"],
    "猫咪": ["小李的站"],
    "萌": ["小李的站"]
  },
  "sources": ["本机", "小李的站"]              // 这个 md5 出现在哪些站
}
```

**为什么是并集而非优先级覆盖**：标签是描述性信息，多一个标签
只会让搜索更准，不会"污染"。覆盖反而会丢信息。

**可选增强**：如果担心标签膨胀，可加一个开关"只显示与当前搜索词
相关的标签"。

### 5.3 其他字段的冲突解决

| 字段 | 规则 |
|---|---|
| `file_size` / `width` / `height` | 取**优先级最高**的站（`mirror_sites.priority` 小的优先）；同 md5 这些值本就该相同 |
| `created_at` | 取**最早**的（图第一次出现的时间） |
| `url` / `thumb_url` | 取优先级最高的站；同时保留 `all_urls` 供切换 |
| `filename` | 取优先级最高的站 |

### 5.4 前端展示

- 缩略图：直接用 `thumb_url` 的**绝对地址**（`<img>` 跨域显示无障碍）
- 卡片右上角显示一个**小徽标**，标明来源站（或"多站"）
- 点击原图：打开该 `url`（或跳转到对应站点）

## 七、延迟影响（这是必须正视的）

实测你的链路线：公网 RTT **860–970ms**。

| 场景 | 延迟 |
|---|---|
| 单站搜索（现状） | ~900ms |
| 聚合 3 个站（后端并行） | **~900ms + 最慢站的时间** |
| 镜像站本身也在穿透链路上 | 可能 **1800ms+** ⚠️ |

**关键设计**：

- **并行请求**（`asyncio.gather`），不是串行累加
- **单站超时 3 秒**，超时就跳过并在 `sources` 里标注
- 前端**先显示本机结果**，镜像结果后到再追加（渐进式渲染）

> 如果镜像站也在慢链路上，用户可能等 2 秒以上。建议 UI 上明确
> 显示"正在查询 N 个镜像站…"的进度。

## 八、安全与治理

| 风险 | 对策 |
|---|---|
| 镜像站返回超大响应 | 限制单站响应体大小（如 5 MB），超出丢弃 |
| 恶意镜像站注入内容 | 严格校验 JSON 结构；`url` 只允许 http/https；标签做长度与字符过滤 |
| SSRF（用户填内网地址） | **禁止** `base_url` 指向内网/回环地址（169.254/10./172.16-31./192.168./127.） |
| 镜像站拖慢主站 | 并行 + 超时 + 结果缓存（同查询 30 秒） |
| 版权/隐私 | 镜像站需自行决定是否公开 |

**SSRF 防护是必须的** —— 用户能填任意域名，必须拦住内网地址，
否则可以借此探测你服务器所在内网。

## 九、需要统筹的按钮分工

FAB 网格共 10 个按钮，当前规划有冲突：

| 按钮 | 当前 | 鉴权方案 | 本方案 |
|---|---|---|---|
| `fab-export` | 导出 JSON | — | **改为镜像站管理** |
| `fab-import` | 导入 JSON | **改为 QQ 登录** | — |

**两个危险操作（导入/导出）都要让位**，需要确定它们的新家：

| 方案 | 说明 |
|---|---|
| **顶部菜单**（建议） | 页面顶部放一个「数据」菜单，容纳导出/导入/镜像站 |
| 规则树面板底部 | 与规则管理放一起，但语义不太相符 |
| 长按 FAB 展开二级菜单 | 手机上不好发现 |

建议采用**顶部菜单**，把"数据管理/镜像站"归为一类。

## 十、实施步骤（建议顺序）

| 步骤 | 内容 | 风险 |
|---|---|---|
| 1 | 镜像站需先提供 `/api/mirror/search` 只读接口（含绝对 url） | 低（但需改各站代码） |
| 2 | 主站建表 + 镜像站 CRUD 接口 | 低 |
| 3 | 聚合搜索接口（并行 + 超时 + 去重 + 合并标签） | **中（核心逻辑）** |
| 4 | SSRF 防护 + 响应体大小限制 | **中（安全）** |
| 5 | 前端：镜像站管理面板 + 结果来源徽标 | 中 |
| 6 | 统筹 FAB 按钮分工，导入/导出迁移到顶部菜单 | 中 |

> **第 1 步是前置条件**：没有镜像站配合，后面都没法测。
> 建议先自建第二个实例（同代码、不同库）做联调。
