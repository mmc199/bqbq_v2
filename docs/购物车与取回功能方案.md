## 一、需求概述

| 需求 | 说明 |
|---|---|
| FAB 按钮 | `#fab-export`（导出 JSON）**改为购物车按钮** |
| 卡片按钮 | 图片卡片上**复制标签按钮的左边**加购物车按钮，可切换"加入/移出" |
| 购物车面板 | 仿现有面板样式，展示购物车内容 |
| 取回方式 | 用户**主动触发**，通过 bot 私聊把图片发到 QQ |
| 实现简化 | **不做检验、失败重发**；已发送的直接移出队列 |

## 二、关键设计决策

### 2.1 购物车存后端，不存前端

**结论：必须存后端数据库。**

| 方案 | 可行性 |
|---|---|
| 前端 localStorage | ❌ **bot 取不到** —— bot 是独立进程，读不到浏览器的 localStorage |
| **后端数据库** | ✅ bot 能查询、能取走、能标记状态 |

购物车按 `client_id` 归属，与鉴权体系共用同一个身份。

### 2.2 不复用搜索接口

**结论：新增专用接口。**

实测 `SearchRequest` 的入参（`models/image.py`）：

```
include_tags / exclude_tags / page / page_size / min_tags / max_tags
sort_by / extensions / exclude_extensions / expand / cursor_id / cursor_ts
```

**没有任何按 md5 列表精确取回的参数。** 购物车取回是"按用户勾选的具体几张"，
与"按标签搜索"语义完全不同，强行复用会污染搜索接口。

### 2.3 不做重发、不做校验

按需求尽量简化：

- bot 发送成功 → 直接从购物车移除（不等用户确认）
- 发送失败 → **不重试**，保留在购物车里（用户可再点一次）
- 不做"已读回执"、"确认收到"等交互

> 这样把 bot 与网站之间的通信降到**单向**：网站写队列 → bot 取走 → 网站删除。

## 三、数据库设计

```sql
-- 购物车
CREATE TABLE IF NOT EXISTS cart_items (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    client_id   TEXT NOT NULL,          -- 谁的购物车
    md5         TEXT NOT NULL,          -- 图片 md5
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(client_id, md5)              -- 同一人同一张图只存一条
);
CREATE INDEX IF NOT EXISTS idx_cart_client ON cart_items(client_id);

-- 待取回队列（用户点"发送到 QQ"后进入这里）
CREATE TABLE IF NOT EXISTS cart_outbox (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    client_id   TEXT NOT NULL,
    md5         TEXT NOT NULL,
    status      TEXT DEFAULT 'pending',  -- pending | taken
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    taken_at    TIMESTAMP
);
CREATE INDEX IF NOT EXISTS idx_outbox_status ON cart_outbox(status, client_id);
```

**为什么购物车和待取回队列分开**

| 表 | 语义 |
|---|---|
| `cart_items` | 用户"收藏"的图，长期保留 |
| `cart_outbox` | 用户"这一次要取走"的图，取走后即删 |

用户可能想保留购物车内容，而不是取一次就清空。

## 四、后端接口

| 方法 | 路径 | 用途 | 鉴权 |
|---|---|---|---|
| GET | `/api/cart` | 列出当前 client_id 的购物车 | 需要登录 |
| POST | `/api/cart/add` | 加入 `{md5}` | 需要登录 |
| POST | `/api/cart/remove` | 移出 `{md5}` | 需要登录 |
| POST | `/api/cart/clear` | 清空 | 需要登录 |
| POST | `/api/cart/send` | 把购物车推入待取回队列 | 需要登录 |
| GET | `/api/cart/outbox` | **bot 调用**：取走待发队列 | 需要登录（bot 的 client_id） |

**`POST /api/cart/send`**（网页调）

```jsonc
// 请求
{ "client_id": "client_abc123", "md5s": ["7f5d...", "8a2c..."] }
// 不传 md5s 表示"把整个购物车发送"
// 响应
{ "success": true, "queued": 3 }
```

**`GET /api/cart/outbox?client_id=client_abc123`**（bot 调）

```jsonc
// 响应：返回该 client_id 的 pending 项，并**同时标记为 taken**
{
  "items": [
    { "md5": "7f5d...", "filename": "7f/5d/7f5d....gif",
      "url": "https://bqbq-img.mmc199.com/meme_images/7f/5d/....gif" }
  ]
}
```

**关键设计：bot 取即标记**

调用 `/api/cart/outbox` 时，后端**立即**把这些行标为 `taken`，
下次不会再返回。这样：

- bot 不需要回调"发送成功"
- 即使 bot 发送失败，也不会重复发（符合"不做检验失败重发"的要求）

> **代价**：bot 崩在取走之后、发送之前，这几张图就丢了。
> 考虑到是"表情包"场景，用户可再点一次发送，可以接受。

### 5.4 取回流程（用户主动触发）

```
① 用户在购物车面板点「发送到 QQ」
      ↓ POST /api/cart/send
   面板提示：「已加入待取回队列，请私聊机器人发送 bqbq取回」
      ↓
② 用户主动私聊 bot 发「bqbq取回」
      ↓
③ bot 调 GET /api/cart/outbox?client_id=bot_xxx
   （或按用户 openid 反查——见 6.2）
      ↓ 后端立即标记 taken
④ bot 用 API 把图片逐张发到私聊
      ↓
⑤ 完成，购物车中的图仍保留（用户可再发）
```

## 六、关键难点

### 6.1 bot 如何知道"取谁的购物车"？

这是整个功能最需要想清楚的地方。bot 收到的消息只带 **openid**，
不带浏览器的 client_id。

| 方案 | 说明 | 评价 |
|---|---|---|
| **A. 用户先绑定** | 用户在网页登录时（已通过 QQ 验证），后端记录 `openid ↔ client_id` 的对应关系，bot 用 openid 反查 | ✅ **推荐**，登录流程本来就有 openid |
| B. 用户发自己的 client_id | 用户在 QQ 里发 `bqbq取回 client_abc123` | ⚠️ 要用户手动抄一长串，体验差 |
| C. bot 取所有人的 | 不安全，会把别人的图发给你 | ❌ |

**方案 A 的实施**：在 `auth_granted_clients` 表里增加 `openid` 字段
（目前已有），登录时写入。bot 收到 `bqbq取回` 时：

```
1. 取 event.get_sender_id() -> openid
2. GET /api/cart/outbox?openid=<openid>
3. 后端用 openid 查出对应 client_id，返回该人的队列
```

> **前提**：一个人只用一个 client_id。若你在多台设备登录，
> 会对应多个 client_id，此时按 openid 会取到多个购物车的并集——
> 这个行为是合理的。

### 6.2 官方 bot 的发送条数限制

你提到的限制确实存在。应按此设计：

| 限制 | 应对 |
|---|---|
| 单次发送条数上限 | bot 每次取 **不超过 N 张**（如 5 张），剩下的留在队列里，用户再发一次 `bqbq取回` |
| 频率限制 | 不做自动重试；用户发一次取一次 |

**接口设计上支持分批**：

```jsonc
// GET /api/cart/outbox?openid=xxx&limit=5
{ "items": [...最多 5 条...], "remaining": 12 }
```

`remaining` 让 bot 能回复用户："已发 5 张，还剩 12 张，请再发一次"。

### 6.3 bot 如何获取图片文件？

bot 有两个选择：

| 方式 | 说明 |
|---|---|
| **按 URL 下载**（推荐） | 接口返回 `url`，bot 用 httpx 下载后发送 |
| 后端直接返回字节流 | 接口更重，且 multipart 处理麻烦 |

用 `url` 更简单——`url` 指向 CDN 或 `/images/`，bot 直接 GET 即可。

## 七、鉴权集成

购物车的所有接口都要求登录态（复用 `require_edit`），因为：

- 购物车是个人数据，按 client_id 隔离
- 防止陌生人往你的购物车塞数据

bot 取队列时用**它自己的 client_id**（`bot_astrbot` / `bot_nonebot`），
但查询维度是**用户 openid**，与 bot 自己的 client_id 无关。

```python
@router.get("/cart/outbox")
async def get_outbox(openid: str | None = None,
                     limit: int = 5,
                     _: None = Depends(require_edit)):   # bot 的 client_id 通过 query 传入
    ...
```
